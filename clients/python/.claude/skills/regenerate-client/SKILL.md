# regenerate-client

Use when the Contractum API changed in a way the SDK consumes (a new field on a consumer response, a
new read operation) or when `scripts/generate_client.py --check` reports a stale client. Work from
`clients/python`.

1. **Refresh the source spec.** The generator reads the merged OpenAPI document
   `ui/openapi/openapi.json` (regenerated by the server tooling, not by the SDK). Do not edit it
   here. Do not import server code: the SDK never imports `dc_*`, `fastapi` or `sqlalchemy`.
2. **Edit the allow-list** `openapi/operations.txt` (one `METHOD /path` per line). It holds the GET
   consumer operations and nothing else: the SDK is read-only towards Contractum and sends no POST
   at all (sign-in is a token only). Adding any write operation is wrong, and the fence test fails
   on it.
3. **Regenerate**, never by hand:

   ```bash
   uv run python scripts/generate_client.py            # rewrite openapi/consumer.openapi.json and src/contractum/_generated/
   uv run python scripts/generate_client.py --check    # exit 1 when the committed client is stale; never writes
   ```

   The generator prunes the spec to the allow-list, drops the `X-Token-Delivery` header and the
   refresh-cookie parameters should an operation carry them, runs `openapi-python-client` and rewrites the generated `httpx2`
   references to `httpx` (the SDK keeps one HTTP stack; `respx` mocks only `httpx`).
4. **Never edit `src/contractum/_generated/`.** It is vendored generator output; a hand edit is
   lost on the next run and fails `--check`. Fix the generator script or its post-processing
   instead, then regenerate and commit the result.
5. **Generator pin (D-45).** `openapi-python-client` is pinned exactly (0.30.0) in
   `scripts/generate_client.py`. Bump it deliberately, regenerate, and check that the `httpx2` to
   `httpx` rewrite still finds references (the script aborts when it finds none). `post_hooks` stays empty in `openapi/generator.yaml` so the
   generator never runs an unpinned formatter.
6. **Keep `_api.py` the only importer.** `src/contractum/_api.py` is the one module allowed to
   import `contractum._generated`. A new operation is wrapped there (typed arguments, the error
   mapping to the closed `ContractumError` taxonomy, no body echo) and added to
   `ALLOWED_OPERATION_MODULES`. The rest of the SDK calls `_api`, never the generated modules.
7. **Update the fence test** `tests/unit/test_generated_fence.py`: the expected operation count
   (`len(_api.ALLOWED_OPERATION_MODULES)`), the all-GET assertion and any new model import. The
   test also checks that `operations.txt` matches the committed pruned spec and that no
   `httpx2` reference remains in `_generated/`.
8. **Models.** A new field the SDK exposes is mapped in `contractum/models.py`, with a unit test;
   the typed public models are not the generated ones.
9. **Gates.** `uv run pytest -m unit -q tests/unit/test_generated_fence.py tests/unit/test_generated_client.py`,
   then `uv run mypy`, `uv run ruff check . && uv run ruff format --check .` and
   `uv run lint-imports --config pyproject.toml`. Coverage stays at the 98 percent floor on unit plus
   integration combined (D-48). Commit `openapi/consumer.openapi.json`, `operations.txt` and the
   regenerated `_generated/` tree together.
